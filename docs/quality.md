# 提交信息质量评估

`test/fixtures/quality.json` 固定了本项目历史中的五组真实改动：Windows 剪贴板、本地规则、Responses 地址处理、协议配置向导、大 diff 整理。记录原始 revision 和文件路径，输入不包含当前工作区、用户配置或凭据。

```sh
npm run evaluate               # 离线列出样本、输入字节数和人工判据，不读取 AI 配置
npm run evaluate -- --run      # 显式向已配置的模型发送五次请求，产生实际用量和耗时
```

每个样本只发一次请求，返回 2 EN + 2 中文。stdout 为 JSON，进度及失败信息写 stderr。`--run` 会产生服务商费用；默认不会联网。样本为固定原始 patch，适合比较模型与提示词，不代替 Git 输入采样的自动化回归测试。

人工逐条记录 `semanticReview`，不要把格式校验通过当作语义通过：

| 维度         | 判据                                           |
| ------------ | ---------------------------------------------- |
| 准确性       | 是否覆盖主要变化，是否编造动机、效果或实现机制 |
| 一致性       | 四条是否指向相同事实，英文和中文是否一致       |
| 类型与 scope | 是否贴合真实改动，是否把维护误写为业务功能     |
| 可采用性     | 直接采用、轻微编辑、重写三档；记录需要改什么   |
| 成本与耗时   | 记录实际 usage 和 elapsedMs，未返回 usage 留空 |

对相同样本、相同服务商和模型比较两版提示词，记录人工采用比例及每条编辑原因。没有真实试用数据前，不宣称采用率提升；没有真实模型调用前，不宣称语义准确性或网络延迟已验证。当前普通测试仅使用本地服务，未发送这些样本至外部模型。

输入压缩另用隔离 Git 仓库测得（与修改前 HEAD 比较，不含提示词）：

| 样本                          | 原输入 bytes | 新输入 bytes |  减少 |
| ----------------------------- | -----------: | -----------: | ----: |
| 单行源码变更                  |           99 |           99 |    0% |
| 约 78 KB 源码，首尾有行为标记 |       78,128 |        4,943 | 93.7% |
| 12,000 行源码                 |       13,615 |        6,117 | 55.1% |

以上是字节数，不是 token 或费用。原版已经对大文件采样，所以改进幅度取决于输入形状。完整文件清单仍保留，文件极多时元数据可以超过源码预算。真实模型输入 token 还包含提示词和 hint；实际用量以服务商 usage 为准。
